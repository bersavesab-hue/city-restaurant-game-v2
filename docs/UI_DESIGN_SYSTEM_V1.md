# 餐饮 V2 UI Design System 1.0

## 1. 设计基准

视觉稿统一使用 **864×1536，竖屏**。

这只是设计坐标系，不是运行时画布。实际手机按照 CSS 逻辑像素布局，禁止把864×1536整体缩放塞进设备屏幕。

正式支持的最小逻辑视口为 **320×568 CSS px**。

## 2. 唯一 AppShell

所有正式页面必须进入同一个 AppShell：

1. Safe Top
2. Global HUD
3. Page Content
4. Global Nav
5. Safe Bottom

HUD 和底部导航独占自己的布局行。页面内容只能存在于 Page Content，不得通过 fixed、负 margin 或绝对定位侵占 HUD/Nav。

不同手机产生的高度差由 Page Content 吸收。

## 3. 屏幕适配

以 height / width 分类：

| 档位 | 比例 | 调整内容 |
| --- | --- | --- |
| tall-phone | >= 2.1 | 减少空白，主视觉可显示更多高度 |
| standard-phone | 1.9–2.1 | 默认设计 |
| wide-phone-tablet | < 1.9 | 增加两侧留白，必要时增加列表列数 |
| landscape | width > height | 仅保证可见，不作为第一版正式布局目标 |

禁止为不同手机型号分别做页面。

## 5. 字体体系

运行时不依赖外置字体文件，优先使用系统字体：

system-ui / PingFang SC / Microsoft YaHei / sans-serif

基础字号：

- Caption 12
- Body Small 14
- Body 16
- Label 16
- Small Title 20
- Title 24
- Display 32

重要数字可以单独放大，但必须使用 tabular-nums，并禁止省略号截断。

## 6. 间距与圆角

间距只使用：4 / 8 / 12 / 16 / 20 / 24 / 32。

圆角只使用：8 / 12 / 16 / 20 / Pill。

禁止页面随手写 13px、17px、23px 等新的基础间距。

## 7. 点击与交互

- 最小点击区域：44×44 CSS px。
- 推荐主要按钮：至少48px高。
- 图标可以小于44px，但点击容器不能小于44px。
- 不允许关键操作只靠文字链接。
- 页面滚动只发生在 Page Content 内。

## 8. 图片规则

地图、门店场景、人物、菜品等美术保持原始比例。

允许：cover 裁切、contain 完整展示。  
禁止：非等比拉伸。

图片只负责视觉，不把动态金额、数量、日期、商圈数量等写死在图片中。

## 9. 动态数据规则

以下内容必须由代码渲染：

- 金额
- 日期和时间
- 数量
- 等级
- 评分
- 状态
- 列表内容
- 进度
- 商圈/门店/员工名称

关键数字必须保证完整展示；空间不足时优先减少非关键说明、缩小间距或改变列数，不能把金额和数量截成“12,4...”这种形式。

## 10. 五个一级页共同纪律

城市、门店、经营、员工、更多只能共享一套 Global HUD 与 Global Nav。

一级页面只能决定 Page Content 内部结构。

五个一级视觉稿全部确认之前，不接正式页面逻辑、不导入正式图片、不建立旧接口兼容。

## 11. 禁止事项

- 禁止恢复 src/ui。
- 禁止旧页面入口别名。
- 禁止整页 transform: scale() 适配手机。
- 禁止按高度百分比把整页硬切成100%。
- 禁止页面自己 fixed 顶栏/底栏。
- 禁止同一功能存在两套CSS。
- 禁止在旧页面上叠加修补。
- 禁止图片与动态数据耦合。
