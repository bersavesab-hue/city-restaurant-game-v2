# 餐饮经营 v2 — UI 与适配规范

## 当前坐标基线
现有移动端代码已经使用 540×960 逻辑参考尺寸，`ScreenAdapter` 会在不同屏幕比例上等比缩放，并通过增加逻辑宽度或高度避免拉伸。

因此当前阶段固定：
- 逻辑参考框：540×960。
- 9:16：完整参考框。
- 9:20 等长屏：保持横向 540 逻辑宽度，增加可用逻辑高度。
- 宽屏/平板：保持参考高度并扩展逻辑宽度。
- 不把 540×960 当作美术资产像素上限。

除非后续有完整迁移任务，否则不得再在 540×960、540×1200、960 宽等坐标体系之间来回切换。

## 四层结构
1. 背景层：餐厅场景、墙面、地板、大面积环境。
2. 固定装饰层：边框、招牌、非数据装饰。
3. 动态数据层：资金、营业额、日期、时间、星级、库存、状态文本。
4. 交互层：按钮、点击区域、弹窗、选择态、列表。

动态数据不得烘焙进背景图。

## 长屏适配
- 背景负责填满扩展区域，可延展或按预定安全区域裁切。
- 顶部信息区锚定安全区顶部。
- 底部一级入口锚定安全区底部。
- 中间内容区吸收额外高度。
- 固定重要内容优先保持原字号和点击尺寸，不通过无限缩小解决空间不足。
- 主页整体不滚动；列表、详情面板等在自己的内容区内滚动。

## 安全区
所有顶部、底部及边缘交互控件必须考虑 `env(safe-area-inset-*)` 对应的逻辑安全区。

## 点击与层级
- 纯装饰默认不接受指针事件。
- 透明 PNG 的空白区域也要检查是否挡住下层按钮。
- 调试工具中的 Z 层级只决定视觉顺序，不允许通过极端 Z 值掩盖错误的 DOM 结构。
- 最终功能控件必须有明确的真实点击目标。

## 内置布局工具
现有 `DevToolkit` 继续作为开发辅助工具，但只承担布局调整：
- 选择控件；
- 调整 x/y/宽/高；
- 设置锚点和层级；
- 锁定/隐藏；
- 显示辅助线和点击区域；
- 导出/恢复布局配置。

首发不把它扩展成通用截图理解、APK 拆包或完整图片编辑器。

## 当前 UI 事实
当前 `HomePage.js` 被明确收缩为“空白设计画布 + 背景层”，测试也要求不存在正式导航、顶部状态栏和经营页面。此状态不是完整游戏 UI。

后续恢复主页时：
- 不直接恢复旧硬编码演示数值；
- 所有资金、日期、星级、成长等必须绑定真实游戏状态；
- 一级入口的点击必须进入真实模块或明确不可用状态；
- 先完成一套主页真实数据绑定，再复制到其他页面。

## 视觉验收
每个正式页面至少验证：
- 9:16；
- 9:19.5；
- 9:20；
- 安全区设备；
- 字体可读性；
- 点击区域；
- 弹窗关闭；
- 长文本/大数字不会破坏布局。
